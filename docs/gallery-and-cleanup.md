# Фотографии Ойнеловских далей и очистка проекта

## Галерея

Пять добавленных владельцем снимков `DJI_0696`, `DJI_0699`, `DJI_0705`, `DJI_0706`
и `DJI_0712` подключены к карусели Ойнеловских далей. Это реальные фотографии
территории, без генерации или изменения композиции. Применены уменьшение размера
с сохранением пропорций и WebP quality 82; метаданные камеры не копируются.

Каждый снимок имеет две версии в `public/images/oinelovo/`: 1280×720 для просмотра
и 640×360 для миниатюр/мобильного блока. В сумме исходные JPEG занимали
20 899 218 байт, все десять WebP — 1 865 306 байт (на 91% меньше).

Оригиналы сохранены без изменений в `private/source-photos/oinelovo/` с SHA-256
и параметрами экспорта в `optimization.json`. Эта папка исключена из Git и релизов;
при переносе рабочего каталога сохраните её отдельно, если нужны оригиналы.

Каталог галереи — `src/data/oinelovoPhotos.ts`. Основной блок, окно из трёх миниатюр
и модальная карусель используют один список; стрелки открывают остальные снимки.
Пути миниатюр задаются явно в каталоге, без замены цифр в имени файла.
Новые обложки hero остаются прежними, фотографии добавлены именно в галерею.

## Очистка

Проверка графа импортов от `src/main.tsx` подтвердила отсутствие использования:

- старых секций `GeneralPlan`, `Info`, их стилей и неиспользуемых barrel-файлов;
- старых `AboutUs.css`, `Projects.css` после редизайна главной;
- статических `heroFacts`, `settlementFormats` и связанных типов/иконок;
- старых фото карточек, декоративного фона плана, `reference.png`, большой версии
  старой аэрофотографии и TTF-дубликатов двух подключённых WOFF2-шрифтов.

Эти файлы и объявления удалены. Исходный lossless-план и PNG перенесены в
`docs/design/source-assets/`: они нужны для будущих экспортов, но не для браузера.
Удалённые владельцем прежние фотографии галереи не восстанавливаются.
Ручные данные `mock/plots.ts`, метаданные отдельных участков и экспортированные базы
сохранены. Архитектура API, схема БД и работа Journal/Telegram не меняются.

## Release

`npm run build && npm run package:hostland` пересобирает два актуальных архива:

- `release/hamper-hostland_YYYY-MM-DD_HH-mm-ss_MSK.zip` — полное приложение для Hostland;
- `release/hamper-public-update_YYYY-MM-DD_HH-mm-ss_MSK.zip` — обновление `public/` без замены API и базы.

В имени указаны дата и время упаковки по Москве. Точные имена свежей пары
находятся в `release/README.md`, время создания и SHA-256 —
в `release/verification.json`. Распакованные каталоги `hamper-hostland/` и
`hamper-public-update/` сохраняют фиксированные имена. После успешного создания
обоих архивов упаковщик удаляет только предыдущие ZIP этих двух типов.

Оба содержат manifests SHA-256 и инструкции. Старые временные startup-патчи и
архивы редизайна убраны после проверки новой упаковки. Выгрузки
`release/hostland-data-2026-10-26/` и `release/hostland-initial/` сохранены отдельно;
это данные, а не лишние файлы сборки. Актуальные снимки интерфейса и результат
браузерной проверки находятся в `release/review/`.

## Проверки

Согласованная граница TDD — действия пользователя в браузере. Новый тест сначала
упал на `3 !== 5`, затем прошёл после подключения WebP: все пять фотографий
загружаются, переключаются кнопками и клавиатурой, при закрытии возвращается фокус.
Далее рефакторинг проверяется существующими UI/API-тестами и production-сборкой.
Проверки ZIP и запуск извлечённого архива выполняются локально, с синтетической
конфигурацией; рабочий сервер, база и реальные сообщения Telegram не используются.

Результаты: TypeScript и production-сборка прошли; 197 тестов и 89 браузерных
сценариев прошли без ошибок JavaScript. Галерея дополнительно просмотрена в
активной вкладке на ширинах 375, 768, 1440 и 1920 px. Перед снимком инструмент
активирует вкладку: в фоне Chrome мог захватывать пустую область уже загруженного
изображения. В пользовательском интерфейсе загрузка и видимость всех пяти фото
также проверяются автоматически.

В обоих ZIP проверены SHA-256, целостность и точное совпадение `public/` с `dist/`;
