# Общие компоненты и границы модулей — 27.10.2026

Применён навык `js-gof`: композиция компонентов, декларативный выбор канала связи
и отделение правил предметной области от HTTP. Дополнительные зависимости,
классы-фабрики и команды npm не понадобились.

## Логотип и контакты

- `Brand` объединяет существующий SVG, название «Хампер» и подпись. Его используют
  шапки и подвалы главной и обоих проектов, а также шапка `/admin/`.
- Общие размеры, типографика, высота шапки и горизонтальные отступы заменяют
  конфликтующие настройки страниц. Цвет учитывает светлый или тёмный фон.
- `ContactPeople` используется на главной, в «Ойнеловских далях» и в секции
  контактов других участков. Для каждого настроенного номера выводятся его
  собственные Telegram и WhatsApp, используя `tg_logo.tsx` и `whatsup_logo.tsx`.
- Кнопки мессенджеров имеют подписи для скринридера и область нажатия 44×44 px.
  Узкие строки переносятся; анимация учитывает `prefers-reduced-motion`.
- Адреса и номера берутся из существующей конфигурации. Отсутствующие каналы не
  заменяются выдуманными контактами.
- Переход по логотипу из админки использует ту же проверку несохранённых правок,
  что и выход. Отмена сохраняет черновик; переход во время сохранения блокируется.

## Клиент и сервер

| Область | Изменение |
| --- | --- |
| Совместные запросы | `waitForSharedRequest` заменяет одинаковые обёртки ожидания в кэшах участков и настроек. Отмена одного потребителя не прерывает общий запрос. Состояние и правила обновления каждого кэша остаются в соответствующем модуле. |
| Проверка участков | `server/plotValidation.ts` содержит правила полей и тип обновления. Их используют HTTP API и импорт данных. |
| Ошибки валидации | `server/validation.ts` содержит общую проверку текста и `ValidationError`. API переводит ошибку в прежний ответ HTTP 400; импорт не зависит от маршрутов или авторизации. |

Формат API, схема SQLite, миграции, сохранение заявок в Journal и очередь Telegram
сохраняются. Сборка Hostland включает новые серверные модули.

## Проверка и выпуск

Проверяются сборка TypeScript/Vite/Node.js, существующие unit/integration тесты,
пользовательские сценарии в браузере и запуск распакованного релиза. Браузерные
проверки сопоставляют геометрию логотипа на разных страницах, соответствие
мессенджеров каждому номеру и сохранность черновиков при отмене перехода.
Актуальные результаты и снимки находятся в `release/review/`.

- `npm run build`: проверка типов и обе production-сборки прошли.
- `npm test`: 197 проверок прошли.
- `npm run test:browser`: 119 основных сценариев и 6 проверок координат прошли;
  ошибок JavaScript нет. Логотипы сравниваются на ширинах 375, 768, 1440 и 1920 px,
  строки контактов дополнительно проверены при 320 px.
- Оба ZIP проверены по SHA-256 и manifest; клиент совпадает с `dist/`.
  Распакованный полный архив проходит запуск Passenger, авторизацию, запись
  заявки в Journal, доставку Telegram с имитацией сети и восстановление backup.
