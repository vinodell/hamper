# Рефакторинг структур данных — 27.10.2026

Применены `data-structures` и `js-data-structures`. Проверены клиентский кэш,
статистика участков, интерактивная карта, административное сохранение, Journal
и доставка Telegram. Внешнее поведение и формат API сохранены.

## Изменения

| Область | Структура и результат |
| --- | --- |
| Статистика главной и проекта | Общий `summarizePlots` принимает readonly-список и за один проход возвращает объект сводки. Убраны параллельные массивы площадей/цен и поиск участка по индексу цены. |
| Минимальная цена | Сводка хранит ссылку на соответствующий участок. При равных ценах выбирается первый участок, как прежде. Главная использует базовые цены и площади свободных участков; проект — площади всех участков и минимальную цену свободных с учётом полной оплаты. |
| Интерактивная карта | Массив сохраняет порядок SVG. Два `Map` индексируют доступные зоны по UI ID и ID участка; hover и selection используют `get`. Для ID зоны сохранён последний элемент, для ID участка — первый подходящий. Индексы пересоздаются при изменении данных. |
| Подготовка зон | Один проход строит индекс участков посёлка без промежуточных `filter`/`map`-массивов. Другие посёлки исключаются, статусы и поля карты не меняются. |
| Пакетное сохранение | `Set` проверяет уникальность ID; параметризованный `WHERE IN` читает только переданные участки, затем `Map` сопоставляет сохранённые цены. Пакет ограничен 500 записями. Прежние валидация, 404 и атомарный `DB.batch` сохранены. |
| Метаданные участков | `Readonly<Partial<Record<...>>>` отражает отсутствие записи для неизвестного ID. Кэш читает только собственные свойства словаря через `Object.hasOwn`. |

Расчёт сводки остаётся O(n), но использует O(1) дополнительной памяти вместо
массивов площадей/цен. Поиск выбранной зоны после построения индекса выполняется
в среднем за O(1). Размер выборки и временного индекса пакетного сохранения
зависит от размера пакета, а не от общего количества участков в базе. Эти свойства
следуют из алгоритма; ускорение работы опубликованного сайта не измерялось.

## Сохранённые решения

Массив подходит для упорядоченных страниц Journal и фотографий, `Map` — для
черновиков и сопоставления сохранённых участков, `Set` — для подписчиков и ID.
В кэше сохранены порядок, общая загрузка, revision-проверки и ссылки неизменённых
записей: одинаковые ответы сервера не вызывают лишних обновлений представлений.

Горячих операций `Array.shift`/`unshift`, очередей в памяти или накопительных
LRU-кэшей в рабочем коде не найдено. Очередь Telegram хранится в SQLite,
обрабатывается ограниченными порциями и сохраняется после перезапуска. Для этих
операций выбраны существующие структуры; дополнительные ADT и зависимости не
понадобились. Количество npm-команд осталось 12.
