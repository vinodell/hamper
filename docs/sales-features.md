# Акции, документы участков и заявки — 19 октября 2026

Начальная точка изменений: `6694886346a29fa42c05a6756a38970c2fd0dc3c`.

## Требования

1. Управлять отображением акционной ленты и процентом скидки через `/admin`.
2. Из таблицы открывать popup участка с кадастровым номером, отметками получения
   ГПЗУ/разрешения на строительство и кнопкой бронирования. Отметки редактируются
   чекбоксами в админке.
3. Принимать заявку только после явного выбора пользователем согласия на
   обработку персональных данных.
4. Отмечать цену в таблице наклейкой «При 100% оплате».
5. При выборе участка на интерактивной карте давать кнопку покупки в ипотеку,
   ведущую на объявление этого участка в Сбере/Домклик. Кнопка сочетает текст
   и выразительную иконку перехода; индивидуальная ссылка задаётся через админку.
6. Использовать Tailwind для новых компонентов и уместных motion-эффектов,
   сохраняя текущую визуальную систему и доступность.

## Принятые решения

- Акция сохраняется отдельной кнопкой **Сохранить акцию**. Тумблер управляет
  лентами на главной и странице Ойнелово, а также карточкой акции над таблицей.
  Процент — целое число от 1 до 100. Цены участков не пересчитываются автоматически.
- Кадастровый номер и ссылка Домклик задаются индивидуально для участка.
  Форма доступна при добавлении участка и в **Документы и ссылка** существующей
  строки. Без данных UI сообщает «Не указан» / «Не отмечено».
- Публичная кнопка **Забронировать участок** выбирает участок в форме заявки.
  Статус участка подтверждается администратором; просмотр popup не резервирует
  участок. Забронированные участки остаются доступными для просмотра документов.
- У забронированного участка на карте рядом с закрытием есть кнопка
  **Уведомить, если участок освободится**. Она открывает заявку с фиксированными
  проектом и участком, отмечает цель обращения в комментарии и требует нового
  согласия пользователя. Заявка отправляется по существующему каналу; новый
  сервис автоматического отслеживания брони не добавляется.
- Ипотечная ссылка показывается для свободного участка при наличии сохранённого
  HTTPS URL на `domclick.ru` или его поддомене. Ссылка открывается в новой вкладке
  с `noopener noreferrer`. Кнопка содержит иконку дома, подпись Домклик и стрелку;
  hover-эффект стрелки отключается при reduced motion. Реальные номера и ссылки
  заполняет владелец сайта.
- Чекбокс согласия по умолчанию выключен. Он не выбирается при бронировании,
  сбрасывается после успешной заявки и блокируется во время отправки.
  И браузер, и API требуют `consent === true`; Telegram получает подтверждение.
- Настройки акции и изменённые строки переживают повторный вход после 401.
  Неизменённые поля черновика принимают актуальные данные сервера.
- Общий компонент документов используется в popup таблицы и карты. Открытые
  сведения обновляются при сохранении в админке. Подтверждённые изменения
  распространяются между вкладками через существующий BroadcastChannel.
- Tailwind подключён через Vite как инструмент сборки, с префиксом `tw:` и без
  Preflight. У popup короткие переходы transform/opacity; существующая лента
  получила кнопку паузы и статичный режим для reduced motion. 3D и новые
  runtime-библиотеки анимации не требуются для этих действий.

## Контракты и миграции

Публичные и административные участки содержат `cadastralNumber`, `gpzuDone`,
`buildingPermitDone`, `mortgageUrl`. Клиент понимает прежние ответы без этих
полей; старые PUT, в которых новые поля отсутствуют, не стирают сохранённые
метаданные. Публичный ответ по-прежнему исключает `street` и `updatedAt`.

`GET /api/settings`, `GET /api/admin/settings` и `PUT /api/admin/settings`
используют `{ promotion: { enabled, discountPercent } }`. Административные
операции проверяют cookie и Origin. Без успешного публичного чтения акция
не выдумывается; ошибка обновления сохраняет последний подтверждённый результат.

Цепочка миграций `0000_initial.sql → 0001_sales_features.sql` работает с пустой
и прежней базой. Workflow применяет только ожидающие миграции перед публикацией
Worker. Общая concurrency-группа выполняет миграцию и публикацию последовательно
для production базы, не отменяя активный запуск. Ручной запуск описан
в [README](../README.md#database-upgrade).
Миграция добавляет поля и таблицу настроек без удаления участков.

## Ревью

Независимые проверки выполнены от указанной начальной точки.

### Standards

Обязательных нарушений документированных правил и существенных code smells
не найдено. Обнаружены и исправлены два дефекта уровня P2:

- Длина ипотечного URL проверяется после percent-encoding на клиенте и сервере.
  Это исключает сохранение ссылки, из-за которой клиент отвергал бы весь каталог.
  HTTP и клиентский регрессионные тесты проверяют отклонение слишком длинной
  Unicode-ссылки и успешное чтение допустимой.
- Миграция базы и публикация Worker сериализованы общей concurrency-группой.
  Параллельные запуски workflow больше не выполняют одни миграции одновременно.

Оба исправления перепроверены независимым рецензентом: открытых замечаний нет.

не найдено. Единственное замечание уровня P2 касалось параллельного выполнения
миграций; исправление описано выше. После повторной проверки открытых замечаний
